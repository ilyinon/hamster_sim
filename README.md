# Low-Poly 3D Hamster Habitat Simulator

A single-file (`index.html`) browser simulation: autonomous low-poly hamsters live, eat, drink, run in a wheel, sleep, socialise, court, breed, grow old and die inside a fully procedural cage. The colony sustains itself over hundreds of generations without overcrowding or lasting extinction.

Everything is generated in code — no models, textures, images, JSON or other assets (the sprite glyphs for hearts/“Z”s are drawn on a canvas at start-up). Three.js r160 and `OrbitControls` are loaded from the jsDelivr CDN as ES modules through an import map.

## Run it

```bash
cd "E:\1.ВИДОСЫ\AI youtube\Sonnet 5.5\Test 3"
python -m http.server 8793
# then open http://localhost:8793/index.html
```

Any static server works (`npx serve`, etc.). An internet connection is required for the CDN (`cdn.jsdelivr.net/npm/three@0.160.0`); if it cannot be reached the page shows a readable error after ~12 s.

URL parameters (both optional):

| Parameter | Effect |
|---|---|
| `?seed=1234` | Reproducible run (reset reuses the seed). Without it every run/reset gets a fresh random seed (shown in the *Lifetime statistics* header). |
| `?selftest` | Runs the headless scenario suite inside the page on separate simulation instances and prints the result (`?selftest=full` = long unattended runs, ~10 s). Click the overlay to close it. |

## Controls and UI

**Mouse / touch**: drag = orbit, wheel/pinch = zoom, right-drag = pan, click a hamster = select (pink/blue ring + marker; ♀ pink, ♂ blue), click empty space = deselect. The cursor turns into a pointer over hamsters. Hamsters hidden inside the house can be selected from the **Roster** chips.

**Keyboard**: `Space` pause · `1 2 3 4` speed 0.5×/1×/2×/4× · `C` reset camera · `F` follow the selected hamster · `H` hide/show the UI · `Esc` deselect.

**Bottom bar**: Pause/Resume · 0.5×/1×/2×/4× · Refill food · Refill water · Auto-care ON/OFF · Reset camera (smooth) · Reset simulation · Hide UI.

**Left panel** (collapsed behind a “☰ Stats” button on phones): day/clock with sun/moon icon, sim time, speed, FPS · living population with target range / cap bar (gold = living, hatched = reserved litter/rescue slots, teal = target range), age groups, sex split, pregnancies + reserved slots, births/deaths/rescues (this run / lifetime), breeding mode badge with the *reason* breeding is encouraged or restricted · food pellets, water level, auto-care status and totals, wheel occupant/usage, sleepers (house x/2) · roster · lifetime statistics with a two-click **Clear statistics** button.

**Right panel** (selected hamster): name, sex, state (+ sub-activity), age in days and life stage, lifespan, health / hunger / thirst / energy / curiosity / social bars, parents, generation, pregnancy (litter size + countdown) or cooldown / readiness, litters, distance travelled, wheel runs, pellets eaten, personality, **Follow** (camera follows, you can still orbit/zoom) and **Deselect**.

**Event feed** (bottom right): bounded list generated by real events — births, pregnancies, courtship, deaths (with cause), social encounters, wheel use, auto-care/manual refills, rescue arrivals, resets.

There are no permanent floating labels over the animals; all information is in the panels or in the 3D world (crumbs, droplets, sleep “Z”s, hearts, wheel dust, sparkles, pouring pellets, bubbles in the bottle, the rescue carrier and swinging door).

## What is in the cage

Tray with lip, teal wire cage (instanced bars/rails, corner posts, top frame), entrance gate with a hinged door and a ramp down to the table, **raised platform with a planked ramp and rails**, **running wheel** (30 slats, spokes, rear stand, entry wedge), **food bowl** with individually instanced pellets (count = pellets that exist), **water bottle** outside the cage with two sipper tubes at different heights (adults / pups) and a real water level, **sleeping house** (2 beds, translucent roof, warm lamp at night), translucent **tunnel**, **chew toy**, 8 hay nests + 3 platform nests, **510 bedding pieces** (2 instanced meshes with per-instance colour/rotation/scale), potted plants and hay on the table.

Rendering: antialiasing, PCF soft shadows (2048 map), hemisphere + ambient + one shadow-casting directional light (sun by day, cool moon light by night — they hand over at the horizon where both are ~0), ACES tone mapping, pixel ratio capped at 1.75, flat-shaded icosphere/box/cylinder primitives, day/night cycle of **180 simulation seconds** (sky gradient, stars, light colour/intensity, lamp).

## Architecture

One `<script type="module">`, organised in numbered sections (search for `*  N. `):

| # | Section | Role |
|---|---|---|
| 1–3 | utilities, **`CONFIG`**, `LAYOUT` | seeded RNG (mulberry32); *all* tunables; habitat geometry shared by logic and renderer (`groundY()` height field for ramps, slot definitions) |
| 4 | `NavGrid` | 0.25-unit grid, obstacles inflated by the body radius, cell kinds (floor, platform, ramp, tunnel, house), A* with 8 neighbours + string pulling, temporary “dynamic obstacles” around stationary animals |
| 5–6 | traits, `Agent` | needs, ageing, health, steering, the state machine |
| 7 | `Habitat` | finite food/water, occupancy slots, wheel physics, ramp/tunnel locks, automatic care, rescue carrier state |
| 8 | `Population` | life cycle, reservations, breeding regime, births, deaths, rescue |
| 9 | `Simulation` | **the one clock**; owns agents, habitat, population, events, environment (day/night), overlap resolution |
| 10 | self-tests | invariant checker + scenario suite |
| 11–17 | rendering | shared geometry/material caches, `HabitatView`, `HamsterView`, pooled `ParticleSystem`, `EnvView`, `CameraRig`, lifetime stats |
| 18–19 | `App`, boot | renderer, UI binding, pointer picking, frame loop |

**Logic/rendering separation.** Everything between `//#region CORE` and `//#endregion CORE` is pure logic with no THREE and no DOM. The renderer only *reads* simulation state (`HamsterView.update(agent)`, `HabitatView.update(sim)`); the simulation talks to visuals through a tiny `fx.emit(kind, x, y, z, n)` interface (a no-op headless). That is what lets the same code run in Node for balance testing:

```js
// node check.js — extracts the CORE region from index.html and runs 6000 sim-seconds headless
const html = require('fs').readFileSync('index.html', 'utf8');
const core = new Function(html.match(/\/\/#region CORE[\s\S]*?\/\/#endregion CORE/)[0] + '\nreturn { HabitatTests };')();
const r = core.HabitatTests.runHeadless({ seed: 2024, seconds: 6000 });
console.log(r.minLiving, r.maxLiving, r.stats, r.vCount);   // vCount = invariant violations (must be 0)
```

**One clock.** `App.tick` computes `simDt = paused ? 0 : realDt × speed` and advances the simulation in sub-steps of ≤ 1/30 s. Behaviour, movement, animation phases (leg cycles, breathing, all `agent.animT`), needs, ageing, pregnancies, automatic care, particles and the day/night cycle all run on `simDt`; view smoothing uses `simDt` too, so pause freezes everything while the camera, OrbitControls and rendering stay live. Camera follow/reset/UI use real time. `realDt` is clamped to [0, 0.1] so a hidden tab never produces a jump.

**Navigation and obstacle handling.** Paths come from A* over the inflated grid (walls, platform block, ramp rails, house walls with a door gap, wheel footprint, tunnel walls, bowl, chew toy), smoothed by line-of-sight tests, followed with acceleration-limited speed and turn-rate-limited heading, arrival slow-down, soft separation from neighbours (never allowed to push into a wall) and a hard overlap resolver. The ramp is physically climbed (`groundY()` gives y, pitch follows the slope) and is a **one-lane resource**: a hamster waits below/above until the lane is free. The tunnel is a one-occupant explore target. Sleeping/eating/drinking animals are temporary obstacles for other agents' path planning, which removed the last systematic deadlocks (corridors blocked by sleepers).

**Animation** (from state, speed and needs only): alternating trot, body bob, head bob, tail; eating head dips + cheek stuffing; drinking on hind legs with a pitch *solved so the snout meets the sipper tip* for the animal's size; grooming, looking around, sniffing; curled breathing sleep with closed eyes; running in the wheel with leg speed tied to wheel surface speed; courtship hopping and circling; nose-nudge gestures during social encounters; pregnancy belly, pup proportions (big heads), senior slouch/squint/grey muzzle; death roll + shrink.

## State machine

```
              ┌──────────── survival needs override optional states ────────────┐
   IDLE ──decide()──► WANDER · SEEK_FOOD · SEEK_WATER · SEEK_WHEEL · EXPLORE · SLEEP · SOCIALIZE · SEEK_MATE
    ▲                                                                              │ arrive / abandon / finish
    └──────────────────────────────────────────────────────────────────────────────┘
   SEEK_MATE ──partner reached & accepts──► COURTSHIP ──completeCourtship()──► IDLE  (pregnancy tracked separately)
   any state ──die()──► DYING ──3.2 s──► removed          entrance ──► ARRIVING ──► IDLE   (rescue only)
```

| State | Sub-states | Notes |
|---|---|---|
| `idle` | micro: look / groom / sniff | decides when the timer ends, or immediately when a survival need is urgent *and actionable* |
| `wander` | – | goal near a random floor point (pups stay near their mother) |
| `seekFood` | go → align → eat → done | reserves one of 3 bowl places; each bite removes one pellet; empty bowl → 1.8 s of trying, then abandon + back-off |
| `seekWater` | go → align → drink → done | reserves one of 2 sippers the animal can reach; each sip removes water; empty → abandon |
| `seekWheel` | go/queue → face → wait → enter → align → run → slow → exit | exactly one owner; others queue ≤ 9 s or pick something else; waits for the spinning wheel to coast down; wheel spin = −dir·speed / radius |
| `explore` | tunnel / platform / chew / sniff scripts | tunnel and ramp are locked; gnawing throws chips |
| `sleep` | go → align → settle → sleeping → wake | house (max 2) → nest → platform nest → any quiet floor spot; minimum bout length, longer at night |
| `socialize` | seek → meet / respond | both partners face each other and exchange nudges, then both are released |
| `seekMate` / `courtship` | seek → dance | needs urge + eligibility + breeding licence; circling dance with hearts; ends in `completeCourtship()` |
| `dying` | – | everything is released at the *start*; the body rolls over and shrinks for 3.2 s |
| `arriving` | – | rescued adult walks out of the carrier, up the entrance ramp and through the door |

**Decision scoring** (`Agent.decide`): food/water scores grow steeply with hunger/thirst (×2 when ≥ 78), sleep grows with `100 − energy + night bonus (+ pup/senior/low-health bonus)`; wheel, explore, social, mating are optional and only considered while `hunger, thirst < 68` and `energy > 30`; age and health scale optional activity (seniors ×0.6, health < 50 ×0.5). Random ±18 % jitter breaks ties. Failed attempts set a per-activity back-off. Survival needs (`≥ 82`) interrupt wander/explore/queue/social/seek states; the wheel run ends early.

**Watchdogs**: no state may run forever (`stateLimit`), paths that make no progress for 3 s are re-planned (twice) and then abandoned, slot/lock owners that are dead or no longer using them are released each step. In all test runs the watchdog fired **0** times.

## Population balance (`CONFIG`, section 2)

Durations are in simulation seconds (1 day = 180 s).

| Group | Values | Why |
|---|---|---|
| `pop` | start **5**, cap **16**, targetMin **6**, targetMax **11**, recoveryBelow **4**, horizon 95 s | 6–11 animals is a lively but uncrowded 24×16 cage; 16 is a hard safety net that the regime never needs in normal play |
| `life` | lifespan **700–1050 s** (≈ 4–6 days), pup < 45 s, mature at **140 s**, full size 190 s, senior from 72 % of life, fertile until 68 % | wide lifespan spread keeps deaths from marching in lock-step; a run of 10–15 real minutes shows births, growth and natural deaths (2–4 min at 4×) |
| `breeding` | gestation **55 s ±10 %**, litter 2/3/4 (35/40/25 %), female recovery **150 s**, male cooldown **70 s**, failed courtship 40 s, courtship 7 s, min health 65, max hunger/thirst 62, min energy 30, conception 90 % | an unrestricted colony would double every ~300 s, so the regime below does the balancing |
| regime | fertility multiplier 1 → 0.15 between the targets, ×1.8 below targetMin, cooldowns ×0.7 (encouraged) / ×0.5 (recovery), colony-wide **pacing** 20 s (small colony) → 300 s (near targetMax), one courtship at a time | see below |
| `needs` | hunger +0.32/s, thirst +0.38/s, energy −0.34/s awake / +0.95/s asleep, seek ≥ 48/46, urgent ≥ 82, critical ≥ 96 with **25 s grace** then −0.9 health/s | brief shortages never kill instantly; prolonged ones do (first death ≥ ~290 s after a total supply cut in the test) |
| `habitat` / `care` | 60 pellets, 100 ml; auto-care visits every 7 s, refills below 45 %, budget = 0.026 pellets/s and 0.030 ml/s **per *target* animal** | supply follows the *target* population, so an oversized colony feels shortages, which close breeding (stock < 12 %) |
| `rescue` | 12 s empty-habitat delay, 30 s no-viable-pair grace, cooldown **120 s**, ≤ 2 adoptees per event, 7 s apart, age 170–260 s | limited, logged, capacity-checked; a first adoptee arrives ~14 s after extinction |

**How the regime works.** Each 0.5 s `Population.computeStatus()` derives:

* `upper = living + reserved slots` and `projected = upper − animals expected to die within 95 s`.
* `upper ≥ cap` → **restricted (hard cap)**; food or water stock < 12 % → **restricted (resources)**; `upper ≥ targetMax` → **restricted (upper target)**.
* `projected < targetMin` → **encouraged** (×1.8 urge, cooldown ×0.7), or **recovery** when ≤ 4 are alive (cooldown ×0.5, relaxed thresholds).
* otherwise the multiplier falls linearly from 1.0 at targetMin to 0.15 at targetMax (“reduced fertility near the upper target”).
* on top, conceptions are **paced** (short spacing when the colony is small, ~300 s near the top), which keeps age cohorts from synchronising (this removed the boom/bust cycle seen with the multiplier alone).

Mating urge accumulates only while an adult is eligible *and* the regime allows breeding; it needs cooldown, health, hunger/thirst/energy checks, a compatible partner (opposite sex, not parent/child) and the courtship to complete.

**Reservations.** When a courtship completes, the litter size is rolled and clipped to `min(roll, cap − living − reserved, targetMax − upper)` and the **whole litter is reserved atomically before the pregnancy exists** (`reserve()` re-checks `living + reserved + n ≤ cap`). A reservation is fulfilled exactly once at birth (a second attempt is counted in `diag.dupFulfil`, always 0) or cancelled exactly once if the mother dies. Rescue arrivals reserve their slot when scheduled and fulfil it when the adoptee appears. `living + reserved ≤ cap` is asserted at every step of the stress tests.

**Rescue.** Triggered when the habitat is empty, or no viable breeding pair exists (a fertile female and male that are compatible, counting juveniles who will mature) and no pregnancy is pending for 30 s while `living < targetMax`. The missing sex is brought in first (both when empty). Natural births still supply ~93 % of all arrivals in the long runs.

**Nothing is faked**: no culling of “excess” animals, no immortality, no resurrection — animals die at their own lifespan or from prolonged critical hunger/thirst; the regime only changes *fertility*.

## Results observed

Headless (same code as the page), all with invariant checks every few steps:

| Test | Result |
|---|---|
| 8 seeds × 9000 sim-s (50 days each, ~80 births and ~80 deaths per run, up to 25 generations) | population 2–11, mean 7.6–8.2, **max living+reserved 11**, never extinct, 0 violations, rescues 1–7 per run (≈ 1–8 % of arrivals) |
| 1 seed × 120 000 sim-s (≈ 670 days) | 1015 births / 1083 deaths / 70 rescues, population 2–11, mean 7.8, 0 violations, 0 watchdog triggers |
| zero population (3 seeds) | first adoptee after **14 s**, pair after 21 s, natural recovery to 6–10 within 1200 s |
| last fertile pair lost (3 seeds) | rescue after **32 s**, births afterwards, no violations |
| hard cap with simultaneous pregnancies (cap 8–20, pacing switched off) | `living + reserved ≤ cap` at *every* step; up to 2 simultaneous pregnancies; a same-step race (5 courtships finishing together, 3 free slots) never reserved more than 3 |
| shortages | 70 s without supplies → 0 deaths; total cut → first death after 287 s |
| death while using wheel / bed / bowl / sipper / tunnel, while courting, while pregnant | occupancy, partner links and reservations released immediately, corpse removed, no stale slots |
| reset during pregnancy | new run starts clean, reservation ledger balances (created = fulfilled + cancelled + pending) |

Browser checks (in-app browser, 1280×720 and 1600×900, plus emulated 375×812 phone): pause freezes sim time and agent ages; 0.5×/1×/2×/4× advance time in exact 0.5:1:2:4 ratio (ages included); manual refills pour progressively (14 pellets/s, 22 ml/s); auto-care toggle; reset (5 hamsters, per-run counters, occupancy, reservations, particles and views cleared; lifetime stats kept); Clear statistics needs two clicks and empties `localStorage`; camera reset tween converges in ~1 s; follow → death of the followed hamster keeps tracking during the death animation, then releases selection, follow and card safely; real pointer events select hamsters and deselect on empty space; resize/orientation changes re-fit the camera and layout; a 3000 sim-second live run (with view sync on every birth/death) produced no console errors, no geometry/texture growth, view count = agent count, bounded event list/feed/particles. Performance with the population forced to the cap of 16: ≈ 3.5 ms per frame (with `gl.finish()`), 541 draw calls, 41 k triangles in the test browser.

Reproduce: open `?selftest` (quick) or `?selftest=full`, or use the Node snippet above.

## Known limitations

* Needs internet for the CDN (Three.js is pinned to r160); no offline fallback.
* Performance was measured in the embedded browser only; on very old GPUs the 2048 shadow map and `backdrop-filter` panels are the first things to reduce.
* Hamster–hamster avoidance is soft (separation steering + overlap resolver); two animals can briefly touch in a corridor before the stuck watchdog re-plans (rare: ~20–40 re-plans per 9000 sim-s).
* The tunnel and the ramp are single-occupancy “lanes”; the tunnel is used for exploring, not for sleeping.
* Only one light casts shadows; sun and moon hand over at the horizon (both are almost dark there, so it is not noticeable).
* Genetics are intentionally simple: traits blend the parents plus noise, fur palette is inherited from either parent (12 % chance of a random palette).
* Hamsters are effectively diurnal/crepuscular by design (they sleep mostly at night) so the viewer sees activity in daylight — real hamsters are nocturnal.
* Balance is tuned for the default cage; changing `CONFIG` is safe (all tests use it), but very different values need re-running the suite.
* Lifetime statistics live in this browser’s `localStorage` only; if storage is blocked they simply stay in memory.
